# Ручная приёмка Windows 11 x64

Статус на момент выдачи: **NOT RUN**. Каждый пункт отметить PASS/FAIL с версией Windows, GPU/драйвера, приложения и кратким результатом. Не считать наличие кода подтверждением работоспособности. При критическом FAIL выключить QuadDesk через Ctrl+Alt+0 или закрыть через трей.

## Подготовка

- [ ] `publish.ps1` завершился без ошибок; сохранить TRX и BUILD_STATUS.
- [ ] EXE запускается на Windows без установленного .NET Runtime и без администратора.
- [ ] Первым появляется выбор дисплея; до выбора окна не меняются.
- [ ] Выбран Haier 3840×2160, основной монитор расположен справа/слева/сверху (отрицательные координаты).
- [ ] Выход и повторный запуск; сохранены монитор, раскладка, настройки. Вторая копия не запускается.

## P0: геометрия и изоляция

- [ ] Quad: 4 зоны 1920×1080 при полном 4K.
- [ ] Main + 3: 2496×2160 + 3×1344×720.
- [ ] Все восемь пресетов переключаются из трея и главного окна.
- [ ] Ctrl+Alt+1…9: только существующие зоны, активное окно только на ТВ.
- [ ] Ctrl+Alt+стрелки: предсказуемая геометрическая навигация.
- [ ] Те же клавиши на основном мониторе ничего не двигают.
- [ ] Tray → «Переместить активное окно»: перемещается последнее внешнее окно, не окно настроек.
- [ ] Окна не получают нежелательный focus/topmost.
- [ ] DPI 100%, 125%, 150%, включая разный DPI мониторов: визуальные границы совпадают.
- [ ] Work area / full bounds: правильные координаты относительно панели задач.
- [ ] Отсоединение HDMI при drag / maximize: без падения и перемещения окон основного монитора.
- [ ] Повторное подключение: правильный целевой дисплей, никакой подмены DISPLAY1/2.
- [ ] Конфликт горячей клавиши: понятное уведомление; переназначение срабатывает.

## P1: snap и maximize

Для Chrome, VS Code, Windows Terminal, Блокнота отдельно:

- [ ] Перетаскивание на ТВ показывает overlay; он не перехватывает мышь/фокус/Alt+Tab.
- [ ] Кандидатная зона подсвечена; отпускание перемещает окно в неё.
- [ ] Resize не вызывает snap.
- [ ] Уход курсора на основной монитор скрывает overlay; отпускание там не двигает окно обратно.
- [ ] Обычный maximize / двойной щелчок / Win+Up ограничивается назначенной зоной.
- [ ] Измерить/описать вспышку при native maximize; при неприемлемом эффекте результат FAIL.
- [ ] Повторный native maximize восстанавливает предыдущую геометрию.
- [ ] Ctrl+Alt+M / Ctrl+Alt+R: явное логическое разворачивание и восстановление.
- [ ] Minimize → restore: окно пригодно к работе.
- [ ] Два окна Chrome имеют независимые состояния.
- [ ] Слишком маленькая зона для приложения: возврат геометрии, нет бесконечного цикла SetWindowPos.
- [ ] Закрытие окна непосредственно во время snap: без падения/stale HWND.
- [ ] «Выключить»: native maximize и F11 работают на всём ТВ; повторное включение возвращает layout.
- [ ] Блокировка Windows/UAC: нет перемещения защищённых окон.
- [ ] Процесс в исключениях не перемещается ни правилом, ни клавишей.

## Производительность

После прогрева 60 секунд измерять 5 минут простоя через Диспетчер задач/Process Explorer:

| Метрика | Результат |
|---|---|
| Средний CPU и пик | NOT MEASURED |
| Working Set / Private Bytes | NOT MEASURED |
| GPU | NOT MEASURED |
| CPU во время drag/maximize | NOT MEASURED |
| Handles до/после 100 операций | NOT MEASURED |

Проверить при активном IDE/браузере: поток чужих WinEvent может создавать нагрузку даже без таймера. Целевые значения из ТЗ не считать измерениями.
