## Pull requests

Keep each pull request focused on one logical change.

Before submitting:

1. Build the project.
2. Run the automated tests.
3. Do not commit local configuration, logs, build artifacts or credentials.
4. Describe what changed and why.
5. Mention any known limitations or regressions.

## Security issues

Do not publish exploitable security vulnerabilities as public issues before
the maintainer has had a reasonable opportunity to assess them.
